# HIGGS in the shared VR interaction services

An empty hand beside a pouch and a loose object offers two possible actions for the same grip. HIGGS owns that choice, the resulting hand use and its physical execution. A consumer supplies its eligibility and gameplay rule through the shared service. HIGGS can report the selected action and its observed outcome so another mod can cooperate with it.

The maintained [English concept](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-en.md) and [Russian concept](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-ru.md) live in Body Pouches. HIGGS owns hand state, input, action selection, possession, physical hand operations and haptics. PLANCK owns its NPC bodies and hit path, VRIK supplies the player pose, PPB supplies anatomy, and Body Slots manages logical interaction regions. Consumers retain inventory selection, crime, harvesting and other domain rules.

The proposed interfaces cover input and release correlation, scoped hand-use sessions, inventory/equipment execution routes, physical support and constraints, copied motion/contact observations and coordinated haptics. Clients negotiate each table and capability independently. Released interface 001 has its original declarations. New observer identifiers and mutation permissions have separate meanings, with explicit version negotiation for the experimental tables.

Every change to the author's gameplay path must enable one of those contracts. Input admission, physical request execution, actual result publication and lifecycle invalidation need calls from the existing runtime. Build declarations and exports connect the new implementation. Internal optimization and unrelated behavior repairs are outside this proposal.

Capability results describe supported operations precisely. A policy for trigger-originated weapon drawing requires a qualified semantic command provider. Exact equipment layouts require an executor that can observe and confirm all affected places and instances. Unsupported operations are rejected before mutation. The [implementation ledger](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/implementation-status.md) records source, build, consumer and game verification separately.

The experimental C SDK groups its existing exports into [hand ownership](../include/higgshandapi.h), [input](../include/higgsinput.h), [observations](../include/higgsobservations.h), [items](../include/higgstransactions.h) and [physical operations](../include/higgsphysics.h). Native physics providers can include [borrowed-body interop](../include/higgsnativeinterop.h) with its [common types](../include/higgsabitypes.h). Previously built clients keep the same exported symbols, table versions and layouts. Consumers rebuilding from earlier experimental headers can switch their include paths to these groups.

HandUseProposals version 2 adds an explicit shared decision window. A client enables it before gameplay with controls released. New eligible button, native grab, native mouth/shoulder release actions and nonbutton proposals collect until the next main maintenance, where persistent provider/action/target keys and effective action priority select a disjoint set before any executor starts. A pending button release cancels its offers; a selected native grab reaches the next held controller sample and retains its matching release. Native grip/trigger aliases for the same target share that native choice. Controls without an eligible candidate keep their default path. Reentrant proposals wait for the next window. Legacy immediate hand/domain/physical admission cannot bypass an enabled shared window; consumers first obtain a selected grant. Version 1 remains independently available with its original admission and ordering behavior when shared windows are absent.

Existing possession and authorized continuation are preserved. Pending native acquisition reserves its hand until delivery/acquisition or release; publishing the held item permits consumption and transfer while grip remains down. Revision-checked session expansion can enter the same window through ProposeResize: only newly requested hands compete, and rejection retains the original session. Renewal and reduction remain immediate. The production regression in [shared_rounds_tests.cpp](../src/test/shared_rounds_tests.cpp) covers mixed arrival orders, native release ownership, invalidation, reentrancy and handoff. These are offline source checks; game behavior remains unqualified.

The separate hand-surface interface performs a passive ray query from the current resolved palm in the current native world. It reports the nearest supported static or moving physics surface, including terrain, with a body UID and leaf shape key. Those identifiers provide copied query evidence and do not pin external body lifetime, identify anatomy, issue a grant or change physics. Support acquisition separately revalidates its target. The header declares the exact observation scope and lifecycle checks.
